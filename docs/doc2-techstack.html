A  ·  Language and runtime

Python 3.12

What
The one language in the project. Every script, every stage, every connector, the web server and the training code.
Why
Three reasons that reinforce each other. The mail protocols, SQLite, an HTTP server and email parsing are all in the standard library, so the POC runs with almost nothing installed. The model ecosystem (transformers, lightgbm, scikit-learn) is Python-first, so training and serving share a language. And the people who will read and change this code read Python.
Why 3.12 specifically
It is what is installed on the build machine. Nothing in the code needs a newer feature; str | None annotations and match-free code mean 3.10+ would run it.
Why not otherwise
A Node or Go service would need a separate Python process for the models anyway. Two languages for a proof of concept is two things that can disagree.

No framework, on purpose

There is no Flask, FastAPI, Django, LangChain, LlamaIndex or agent framework anywhere in the project. Flask and FastAPI were checked and are simply not installed; the web page was written on http.server instead so that the POC needs no install step to be looked at. Agent frameworks were rejected for a stronger reason: the safety of the system depends on the approval gate being ordinary Python that never sees email text, and on instruction text and email text never sharing a code path. A framework that routes everything through one model loop removes exactly that separation. Sir also specifically refrained from an MCP-server style design; the chat surface is a plain read loop with a multiple-choice question our code constructs.

C  ·  Reaching the mailbox

google-api-python-client + google-auth-oauthlib — the Gmail API door

What
Google's official Python client for the Gmail REST API, and the OAuth 2 flow that gets a user's consent. credentials.json identifies our app to Google; token.json holds the user's grant and refresh token.
Why
The richest access: push, native labels, threads, history.list ("what changed since X" for one quota unit), and the label-removal feed that makes corrections made inside Gmail visible.
How it is constrained
Two scopes, gmail.modify and gmail.send. The full-access scope that allows permanent delete is never requested. Headers are fetched by name with format=metadata, so an envelope scan never downloads a body.
The cost, and why it is not the only door
Google's CASA security audit ($540–3,000 a year, repeated annually) before the OAuth screen can serve more than 100 users; 7-day token expiry until approved; 2–3 months of approval. A billing rule, not a technical one.

IMAP + an app password — the free door

What
The protocol every mail server speaks, authenticated with a 16-character password Google issues from the account's security page. No OAuth screen, so none of the audit, expiry or user cap.
Why it is not a downgrade on Gmail
Gmail's IMAP advertises X-GM-EXT-1, which adds X-GM-RAW (the full Gmail search language over IMAP, including category:primary), X-GM-LABELS (real labels, readable and writable) and X-GM-THRID (real thread ids). Measured: 45 of 47 audited capabilities work.
What it genuinely lacks
Server push (IDLE exists but holds a socket per mailbox; we poll by highest UID every 20 s) and snooze. Everything else, including sending, is covered.
Limits, measured
2,500 MB/day download cap: our whole design uses 2.3% on the first day. 15 simultaneous connections per account: we use one or two. Sending: 500 recipients/day on consumer Gmail.

SMTP — sending through the free door

smtp.gmail.com:587, STARTTLS, the same app password. Measured 4.9 s for a delivered message with the copy filed in Sent. It is called from one place only, the executor in stage 14, after the gate.

Not yet: Microsoft Graph, JMAP, Zoho

Each is one new connector file behind the same interface. Deferred because sir asked for Google only for now. Proton is impossible (end-to-end encrypted); iCloud was declined (no API, only a password route).

E  ·  Models and machine learning

transformers + torch — the two XLM-RoBERTa models

What
Hugging Face transformers loads and runs the models; PyTorch is the numerical engine underneath. Two fine-tuned copies of xlm-roberta-base (278M parameters, MIT licence, multilingual) are on disk: the stage-8 classifier in classifier/ (547 MB) and the stage-10 name finder in pii_model/ (1.1 GB).
Why XLM-RoBERTa-base
Multilingual — the market is the US, Canada and the UK but mail is not only English, and a test mailbox here contains Urdu. The right size to run on a laptop CPU in ~110 ms. And stable: mdeberta-v3-base was tried first, trained fine for one epoch and then collapsed to a single class with the loss going to NaN. XLM-R is the same size and better behaved.
Why two copies, not one
Different heads: sequence classification (one label per email) versus token classification (one label per word). Same base, two jobs.
Loaded once
Both are loaded once per process and held in memory. Loading a 1 GB model per email would be slower than the API it replaces.
Why not a 7B open model
Sir's requirement was 10–100M parameters, CPU-runnable. 278M is already above that band, which is why ONNX 8-bit shrinking is in the plan; a 7B model would need a GPU per worker.

lightgbm — the reply gate

What
Gradient-boosted decision trees. 300 trees over 17 features. Under 1 MB on disk; trains in 0.24 s on 5,895 rows.
Why trees and not a neural network
The features are tabular (counts, rates, booleans, hour of day). Trees are the right tool for tabular data, train instantly per user, are cheap to retrain weekly, and give feature importance for free. A neural net would be slower to train, harder to explain and no better on seventeen numbers.
Why per person
"Will Yahya reply to this" has nothing to do with what Sara does; a shared model averages away the signal. It is also a privacy requirement: Google's terms forbid pooling many users' mail into one model.
Honest number
AUC 0.684 against a published ceiling of 0.72–0.79, which is why it is blended with hand-set weights rather than trusted alone.

scikit-learn + numpy

TfidfVectorizer turns the person's past replies into 384-dimension vectors for stage 19's "find the four most similar replies", compared with a dot product in numpy; roc_auc_score evaluates the gate. Production swaps TF-IDF for sentence embeddings and the numpy search for pgvector; the code is written so that swap is one class.

google-genai — Gemini

What
Google's client for Gemini. gemini-flash-latest first, with gemini-2.5-flash, gemini-flash-lite-latest and gemini-2.5-flash-lite as fallbacks when the free tier is busy. One client per process.
Used for
Writing the draft (stage 11); reading an email only when our classifier's confidence is under 0.65 (stage 6); picking which date phrase is the real deadline; the chat's multiple-choice interpreter when rules do not match; the eight one-line summaries in the brief; and, during training, labelling ten emails per request as the teacher.
Why Gemini in the POC
A free tier that is enough to prove the flow. Production chooses between Claude and Gemini by blind comparison on real drafts, not by benchmark.
What it never sees
Anything that did not pass through stage 10. Names, numbers and addresses are placeholders; the text is cut to 3,000 characters.

datasets · accelerate · sentencepiece · protobuf — training only

datasets downloads ai4privacy/pii-masking-200k; accelerate drives the Hugging Face Trainer; sentencepiece and protobuf are the XLM-R tokenizer's dependencies. None of these run in production.

Kaggle's free T4 GPU

Fine-tuning a 278M model on a laptop CPU takes 20–40 minutes; on Kaggle's free T4 it takes about three. kaggle_train.py and kaggle_train_pii.py are notebooks-as-files: upload the data, paste the file, run, download the folder. Two hard-won notes live in the file: use the T4, not the P100 (compute capability 6.0 is below what Kaggle's PyTorch build supports), and restrict to one GPU, because the Trainer's DataParallel over two cards fails on 199 examples.

Planned: ONNX Runtime, 8-bit

shrink_model.py exports the classifier to ONNX and quantises to 8 bits: ~1.1 GB → ~280 MB, measured elsewhere at roughly 14× faster on CPU, and production never installs PyTorch, taking the container from gigabytes to megabytes. Written; not yet run.

F  ·  Storage

SQLite now, Postgres later

One file, mailbox.db, nine tables (see Document 1, Part D). Chosen because it is in the standard library, needs no server, and every query in the POC is small. Production is Postgres with the same schema and pgvector for the style vectors. No query relies on anything SQLite-specific, so the swap is a connection string and a migration.

Why no separate vector database

Stage 19 needs "the four past replies most like this situation": thousands of vectors per user, a few searches a day. Postgres with pgvector does that. Adding Pinecone, Qdrant or Weaviate would mean running a second system for a job the first one handles, and a second place user text would live.

JSON files, and why they are not tables

applied_labels.jsonEvery label the sorter or watcher applied, with which door applied it. Read by sort_mailbox.py --undo and by the IMAP label-removal check. A file because it must survive a database reset and be readable by eye.
user_sensitive.jsonDomains the Owner marked private. Read fresh on every call to stage 3 so a mark takes effect at once.
gate_model.jsonMetadata beside the LightGBM model: feature order, AUC, sizes, when trained. The feature order is what makes the model loadable safely.
labelled.jsonl · labels.txt · to_label.txtThe classifier's training data and the hand-labelling round trip. Local only; delete when labelling is done because whoever labels reads the content.

prompts.md — prompts as a document

Every instruction the system gives any model is in one Markdown file with six sections: classify, pick_deadline, draft_reply, read_command, clarify, summarise_for_brief. pipeline/prompts.py loads it. Wording is a product decision; sir can change how the system speaks without a developer, the prompts can be reviewed and versioned, and "what are you telling the AI?" has one honest answer.

G  ·  Surfaces: web and terminal

http.server + hand-written HTML and CSS

What
A single Python file serves four routes: the list, one message, "how it works", and a favicon no-op. The CSS is a small token set with a dark-mode media query. No JavaScript framework, no build step, no npm.
Why
A POC that needs twenty minutes of setup before anyone can look at it does not get looked at. And the page only reads: it renders decisions already in the database, so there is no second copy of the logic that could disagree with the pipeline.
What it is not
A production web server. One user, localhost, no auth. The production view is the same HTML behind a real server, or the WhatsApp channel the design specifies.

The terminal

Every script prints with ANSI colours (a small C dictionary of escape codes) and os.system("") on Windows to switch them on. Output is designed to be pasted into a chat and read, which is how most of the debugging in this project happened. The -X utf8 flag is needed on Windows consoles for subjects containing characters outside cp1252.

I  ·  What is deliberately not used

Not usedWhy not
Our own SMTP server or mail clientSir's hard constraint. We are a layer on top of mailboxes people already have; every company that tried to own the whole mail experience here has died or been sold. Sending goes through the provider's own SMTP or API.
The full Gmail scopehttps://mail.google.com/ permits permanent delete. Not asking is stronger than promising not to.
A vector databasePostgres with pgvector does the one vector job the system has.
An agent framework / MCP serverThey collapse instruction text and email text into one model loop, which is exactly the separation the safety of the system rests on. Sir refrained from it explicitly.
A web framework or JS buildNothing to install; nothing to break; the page only reads.
A model for date arithmetic, sensitivity, or the approval gateModels score below chance on date arithmetic; the gate must be un-arguable; sensitivity must be certain, not probable.
Summarising the whole mailboxThousands of paid calls to produce a wall nobody reads. The brief summarises at most eight things that survived the pipeline.
Body-link unsubscribeClicking through a stranger's page automatically executes whatever that page asks. Only RFC 8058 one-click is done.
