Node B — the processing pipeline

How the Agent Thinks

Every email falls through four layers. Each one either answers confidently or says "I don't know" and passes it up. Only the last layer costs money — and only replies ever reach it.

What each tool actually is

LayerToolWhat it doesWhat it can't doCost
1 email
flanker		 Takes a raw email apart — sender, subject, headers, body, attachments. flanker is Mailgun's, up to 20× faster than the standard library. Nothing. This is a solved problem. Free
1 our own
header rules		 ~200 lines. Checks for the unsubscribe header, Precedence: bulk, noreply@ senders, bulk-mail providers, and whether you've ever replied to this sender. Can't tell an automated receipt from a real person — transactional mail deliberately omits those headers. Free
2 duckling Facebook's, open source. Pulls out dates, times, money, numbers, durations — and gives a probability for each result, which is what tells us when to escalate. Composite durations ("two days and three hours"). Date ranges are experimental. Five languages. Free
2 dateparser Dates only, but very good at them — "in 2 days", "tomorrow", "3 months and 1 week ago". 200+ language locales. No money, no numbers. Around 36% on deliberately messy text. Free
3 ModernBERT
+ SetFit		 Our own small model. SetFit is a training method that reaches ~92.7% accuracy from 8 labelled examples per class — so about 64 hand-labelled emails builds a working classifier. Can't write. Needs its answers checked against the original text before we trust them. Our CPU
4 frontier model Writes the reply, in your voice, using 4–5 of your own past emails as examples. Everything else — it's overkill for anything with a checkable answer. Costs money

When does it hand over to the next layer?

Every layer returns an answer and a confidence. These are the actual rules:

LAYER 1 — header rules
  deterministic: the header is there, or it isn't
  → no clear signal either way ......................... ESCALATE

LAYER 2 — duckling / dateparser
  → duckling's top result scores below 0.80 ............. ESCALATE
  → two results within 0.10 of each other .............. ESCALATE (ambiguous)
  → nothing found at all ............................... ESCALATE

LAYER 3 — our model
  → top category scores below the threshold ............ ESCALATE
  threshold set from real data, not guessed

LAYER 4 — or, if it isn't a writing job ....... SHOW THE USER

And one more gate on top: verify before trusting

model says: deadline = 2026-09-15, quote = "before 15 September 2026"

  does that quote appear in the email? .......... ✗ → THROW AWAY
  is the date in the future? .................... ✗ → THROW AWAY
  does the date match the quote? ................ ✗ → THROW AWAY
Why this matters

Confidence is not trust. A model can be confident and wrong. Because every answer below layer 4 is checkable against the original text, we can catch that automatically and discard it.

Writing is the one job with no checkable answer — there's no automatic test for whether a draft sounds like you. That's why it's the only thing we pay for.

The model decides. The code acts.

Percentages are current estimates and must be measured against a real 1,000-message mailbox before the cost model is relied on. Library capabilities and the SetFit accuracy figure are from published documentation and benchmarks.
