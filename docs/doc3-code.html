B  ·  How to read this code

1 · Every file opens with why it exists

The module docstring is the design note. It says what the file does, the commands that run it, and the reasoning — usually with a measured number. Read the docstring first; the code below it will then make sense.

2 · ⚠️ marks a decision that was not obvious

A ⚠️ comment sits beside code that was written the way it is for a reason a reviewer would need: what was wrong before, how it was found, why the fix is this and not the alternative. Many name the run in test_runs/ that found the problem. If you are about to change a line under one of these, read it first.

3 · Stage numbers are names, not an order

stage09_gate.py is "stage 9" everywhere: in the code, the documents and the meeting notes. The execution order differs from the numbers (3 before 2; 16 after 7; 6 after 8) and Part E gives the real order. There is no stage 18.

4 · No provider name above the connector line

Only connect.py and connectors/ contain "gmail" or "imap". Everything else asks conn.supports_*. If you find yourself writing if conn.name == ... in a stage, the capability flag you need is missing from base.py; add it there.

5 · Two kinds of id, and which is which

message_id is the RFC header (looks like <abc@mail.example.com>) and is the real key. provider_id is the door's handle: a 16-character hex string from the API, or a short all-digit UID from IMAP. Never fetch by a stored provider_id directly; go through connect.fetch_verified.

6 · Reversible vs irreversible is a set, not a judgement

stage13_approval.IRREVERSIBLE = {"send", "forward", "unsubscribe", "trash"} and REVERSIBLE = {"label", "archive", "mark_read", "snooze", "remind", "rescue_from_spam", "draft"}. A new action must be added to one of them or check() refuses it.

7 · Print is not record

A verdict is recorded only by store.record_decision, an action only by store.record_action. Printing it is not enough; the watcher printed verdicts for weeks and recorded none. If a surface makes a decision, it writes it.

D  ·  The data shapes that cross boundaries

Envelope — connectors/base.py

A dataclass. Required: provider_id, message_id. Then, all defaulted: thread_id, account, sender, sender_name, sender_domain, recipients, subject, date, size, unread, in_inbox, categories, unsubscribe, one_click, list_id, bulk, auto_submitted, in_reply_to, references. The defaulted field account must stay after the required ones (a dataclass cannot have a default before a required field). No body.

facts — from stage04_headers.read(env)

{machine_generated, has_unsubscribe, one_click_unsubscribe, list_id, auto_reply, is_reply, addressed_only_to_me, auth: {checked, passed, note}}. Booleans and one nested dict. Consumed by stages 9, 16 and the surfaces.

hist — from store.history(address, me)

{sent, opened, replied} — counts of messages from this address, how many were opened, how many we replied to. replied works only because the recipients column exists; before it was added this count was always zero and the gate's heaviest feature was permanently false.

labels — from local_classifier.classify() or model.classify()

{intent, topic, confidence, by} plus, when escalated, escalated_from, or note when escalation was skipped. intent is one of the two binary labels from our model or one of the six from the Gemini prompt; stage09_gate.REQUESTING lists the values that count as "a request" from both vocabularies.

sc — from stage09_gate.score(labels, facts, hist, env)

{act_probability, needs_reply, first_contact, scored_by, signals, why}. needs_reply = act_probability >= 0.45 and signals["is_a_request"]. why is the comma-joined list of true signals and is what gets recorded and shown.

cands — from stage07_dates.find_candidates(text)

A list of {phrase, resolved (ISO), days_away, looks_like_deadline, context}. Empty when nothing looked like a date.

forms — from stage05_forms.extract(attachments, html)

{meetings: [...], passes: [...], invoices: [...], fingerprint}. stage16.label_key(commitment, forms) uses only these declared sources to pick a category label.

commitment — from stage16_commitments.from_email(env, cands, forms, facts)

{due, kind, remind_at, why, source} or None. source is "attached invite — declared, not inferred" or "found in the text".

Approval — stage13_approval.Approval(action, draft)

Holds hash = sha256(draft)[:16], requested_at, granted. grant(typed) returns (ok, reason); it is an exact match against AFFIRMATIVE and expires after 24 h. check(action, draft, approval) is the gate; execute(...) is the only place a connector's write methods are called from the pipeline.

state — in chat.py

{current_draft, draft_to, draft_subject, approval}. user_input.allowed_actions(state) builds the multiple-choice list from this: with no current_draft, "send" and "edit" are not offered, so no phrasing can produce them.

K  ·  How to add a connector, a stage, a prompt, an action

A connector (e.g. Microsoft Graph)

  1. Create connectors/graph.py with a class that implements every method in base.Connector and sets every supports_* flag honestly.
  2. Return an Envelope from fetch_envelopes with no body. Fill account.
  3. Implement find_by_message_id so connect.fetch_verified works.
  4. Add the choice to connect.open_mailbox(). Nothing else in the project changes.
  5. Run audit_imap.py's equivalent against it before claiming anything.

A stage

  1. Create pipeline/stageNN_name.py with a module docstring saying why it exists and what it must never see.
  2. Give it a pure function that takes the shapes from Part D and returns a dict.
  3. Call it from agent.run_one at the right point in the execution order, and print a stage(NN, ...) line.
  4. If it decides something, store.record_decision. If it acts, go through stage13_approval.execute, and add the action to REVERSIBLE or IRREVERSIBLE.

A prompt

Add a ## name section to prompts.md. Use {placeholders}. Load it with prompts.get("name", **fills). Anything that reaches it from an email must have passed through stage10_redact.redact first.

An action the executor can take

  1. Add the connector method to both connectors (or raise clearly on the one that cannot).
  2. Add the name to IRREVERSIBLE or REVERSIBLE in stage13_approval.
  3. Add its undo to the map in execute(), and a branch that calls the connector.
  4. Add a plain-English name in history.PLAIN.

L  ·  Known gaps and sharp edges

watch.py has its own stage walkhandle() duplicates part of run_one. It records stage-9 decisions correctly now, but any new stage must be added in both places until it is made to call run_one.
waiting.py is API-onlyIt calls conn.svc.users().threads() and the labels API directly. Needs a connector-level "thread of" and Sent-folder access to work over IMAP.
IMAP UIDs are per folderA UID from list_spam() is only meaningful with the spam folder selected. rescue_from_spam handles this; anything new that takes a UID from another folder must too.
Old rows saved with sequence numbersRepaired on 2026-09-11 (test_runs/repair_stale_ids_*.txt). Any database from before that date should be checked the same way before trusting its IMAP ids.
Python heredocs in this shell eat backslashesWriting Python source through a bash heredoc turned \n into a real newline and \b into a byte. Use the editor, or build escapes with chr(92).
The two model folders are large547 MB + 1.1 GB. They are not in any repository; they are rebuilt from the Kaggle notebooks. shrink_model.py is the path to something shippable.
The sample-based numbers moveAnything measured on "the 25 newest" changes daily. The limits test weighs every message for that reason; if a figure must be defended, measure everything.
Gemini key hygieneA key was exposed in a chat during the project. Rotate it, and never print it.
